# 枝迹（BranchTrace）— 品牌与工程命名规范（v1.0）

## 1. 已确认的名称

| 项目 | 值 | 说明 |
|---|---|---|
| 中文产品名 | **枝迹** | 应用窗口、菜单、安装器的首选显示名 |
| 英文产品名 | **BranchTrace** | 英文展示和技术文档使用 |
| 开发代号 | `branchtrace` | Git 仓库、目录、JS 包名等使用 ASCII |
| 产品定位 | 项目树 + 每日实际行动轨迹 | “Todo”只是功能类别，不是正式软件名 |
| 第一版版本 | `1.0.0`（规划版本） | 仅作目标版本，不表示已发布 |

建议宣传语：**让项目有枝可循，让行动有迹可寻。** 宣传语不影响界面业务功能。

## 2. 应用内的显示规范

- 软件标题栏、关于页：`枝迹`，可在关于页附加英文名 `BranchTrace`。
- 顶部两个主视图按钮继续使用 `Project / Daily`（用户界面若本地化为中文可展示 `项目 / 每日`）。
- 统一回收站与主题设置仍为全局入口，不成为第三主视图。
- “项目”“推进”“完成”“取消”“独立提醒”等业务术语保持需求规格中的含义，不随产品名变化。
- **不改变**现有 SQLite 表名、字段名、状态值、Rust Tauri Commands 或 TypeScript DTO；更名仅涉及产品识别和工程元信息。

## 3. 工程与安装命名建议

在创建实际工程时使用以下约定；它们是实现指导，不代表此设计包已经包含可运行的桌面程序。

| 配置位置 | 建议值 |
|---|---|
| 仓库目录 | `branchtrace/` |
| `package.json` 的 `name` | `branchtrace` |
| Cargo package / crate 名称 | `branchtrace` 或 `branchtrace_lib`（与实际脚手架一致） |
| Tauri `productName` | `枝迹` |
| Tauri `version` | `1.0.0`（规划值） |
| SQLite 文件名 | `branchtrace.sqlite3` |
| Logo/图标文件 | 待正式设计；本包不包含图标 |

示例配置片段（**不是完整 `tauri.conf.json`**）：

```json
{
  "productName": "枝迹",
  "version": "1.0.0",
  "identifier": "com.YOUR_OWN_NAMESPACE.branchtrace"
}
```

**重要：** 上述 `identifier` 是明确的占位示例，不应直接复制用于发布。选择实际、稳定且具有使用权的反向域名标识，并验证其符合 Tauri 2 和平台打包要求。应用标识会影响操作系统中的应用身份、数据目录和升级路径；首次公开发布后如需变更，应规划本地数据迁移。产品名、商标、仓库名、域名和包标识在正式发布前均应独立核查可用性。

## 4. 本地数据目录与用户数据

- SQLite 文件必须放在各操作系统的**应用专属数据目录**，不要放入程序安装目录或当前工作目录。
- 应用数据路径应根据最终 Tauri `identifier` 及系统规范计算，不在 Rust 中硬编码 Windows/macOS/Linux 的绝对路径。
- 数据库文件建议命名为 `branchtrace.sqlite3`；需要备份时应考虑 SQLite WAL 文件一致性，不能在写入期间简单复制主数据库文件并声称完成备份。
- 第一版仍然不提供账号、云同步、自动备份和导入导出；这里只是为未来迁移明确命名规范。

## 5. 与原设计包相比的改动范围

1. 文档标题、交付说明及 SQL 顶部注释中的产品名称统一为“枝迹（BranchTrace）”。
2. 增加本文件，约定显示名称、开发代号、数据库文件名及未来打包配置。
3. **没有修改** Project / Daily 的交互规则、数据表结构、字段、SQL 迁移版本和 Rust API 签名。
4. 本交付仍为需求与技术设计文档，不含可运行 Tauri/React/Rust 工程源码或安装程序。
